# Request 027 — equipment, carrier and protection boundaries

Receiving repositories are not changed by this project. The contracts below
exist in host source only and remain unexecuted.

## LH2DT equipment result ownership

Expose stable public producer verification for original compressor stage/train
results and finite heat-exchanger traces. Preserve exact native object/source
provenance, accepted inventory rows, explicit clock and failure prefix.

A future compressor capacity/map level must accept a source-qualified map with
units, speed/flow coordinates, interpolation domain and surge/choke boundaries.
Do not infer a map from the current prescribed ratio/efficiency solver. A
flowing exchanger level needs explicit material ports, pressure loss and spatial
flow ownership; do not reinterpret the closed two-inventory reference.

Acceptance requires the `compressor-boundaries` and
`heat-exchanger-boundaries` profiles plus original equipment regressions,
native package/source audit and installed-artifact replay.

## Carrier conversion

The host preserves finite rich/lean/NH3/N2/H2 inventories, common caloric
reference, imposed conversion extent and actual withdrawal packets. Provide
source-qualified liquid LOHC thermochemistry, catalyst kinetics/equilibrium and
explicit separation/product ports as distinct levels. Gas-reference QM9 heats
cannot qualify liquid operation. Do not infer release, purity, pressure work,
heat recovery or industrial capacity from generated H2.

Acceptance requires both carrier profiles, native caloric definition checks and
independent material/reactor evidence appropriate to the selected level.

## Monitoring and protection

Add a public `verify_result(result) -> same original result` hook to the native
monitor owner. It must check the registered held-out evaluation, trained state,
source partitions, masks, clock/mode rows and unchanged original caches without
rerunning fit or inference. The host currently uses the version-bound private
read-only guard because no public hook exists.

Protection reliability, detection coverage, actuator failure and common-cause
dependence require explicit source evidence. A resolved alarm-to-action path
must not receive a second renamed reliability credit. Online control, fault
causation, mechanical stroke and source-to-field coupling remain separate
levels. Acceptance requires `facility-protection` plus the original monitoring,
dynamic equipment, relief and conditional-risk suites.

The host `FacilityRiskResult` now has a `require_current()` boundary for its exact
native conditional-risk result, finite source, accepted protection run and
dependence declaration. Direct wrapper construction is rejected, and the deferred
facility native-chain case covers replacement with a different dependence object.
This receipt-integrity contract does not qualify the consequence model, input
probabilities, dependence evidence or facility risk result.

No listed profile has run against these source bytes. Historical results do not
validate these contracts.
